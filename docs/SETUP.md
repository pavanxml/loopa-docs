# Setup and commands

[Documentation index](README.md)

These instructions are for the [LOOPA application repository](https://github.com/pavanxml/loopa). To build or host this separate documentation website, use [Publish these docs](DOCS_SITE.md).

## Requirements

- Git, Node.js **24**, and npm. `package.json` declares Node `>=22.16.0`; Node 24 is the documented setup target.
- A writable project directory and persistent storage for SQLite and uploads.
- Optional `ffmpeg` and `ffprobe` on `PATH` for video thumbnails and duration/dimension extraction.
- SMTP credentials only when you want real verification/reset emails or production startup.

There is no separate Express server or MongoDB installation. You do not need PostgreSQL or Prisma migrations to run this application.

Check the tools:

```sh
git --version
node --version
npm --version
```

## Clone and run

These commands work in PowerShell and Linux/WSL:

```sh
git clone https://github.com/pavanxml/loopa.git
cd loopa
npm ci
npm run setup
npm run dev
```

Run npm commands from the folder containing `package.json`. If using a downloaded ZIP with nested folders, enter the inner application folder first.

Open http://localhost:3000, choose **Sign up**, and create your own account. Keep the server terminal open. Stop it with **Ctrl+C**. Start it again later with:

```sh
cd loopa
npm run dev
```

The `cd loopa` command assumes you are in the parent folder. If already in the application folder, run only `npm run dev`.

`npm ci` installs the locked dependency versions. `npm run setup` creates `.env` with a random session secret if the file does not exist; it preserves an existing file. The backend creates the SQLite tables when it opens the database. Development does not require SMTP to sign up or post, but email delivery will remain queued without it.

## Optional demo data

For an empty local development database, before starting the app:

```sh
npm run db:seed
npm run dev
```

Demo login: **maya** / **loopa1234**. The seed skips databases that already contain users and refuses to run with `NODE_ENV=production`. Do not seed an instance you plan to make public; demo credentials are documented and shared.

The seed command uses environment variables inherited by the shell and otherwise the default `.data/loopa.db`. It does not load `.env` itself. If you have intentionally configured a different development database in `.env`, use:

```sh
node --env-file=.env --import tsx prisma/seed.ts
```

## Configuration

Use [.env.example](https://github.com/pavanxml/loopa/blob/main/.env.example) as the reference. Keep real values in your private `.env`, not in Git. Restart the app and mail worker after configuration changes. Use the same database path and application URL for both processes.

| Variable | Default / requirement | Purpose |
| --- | --- | --- |
| `APP_URL` | Setup writes `http://localhost:3000` | Browser origin, email links, and OAuth callback base; HTTPS required by `npm start` |
| `JWT_SECRET` | Random value generated by setup | At least 32 characters; rejects known placeholder values |
| `SQLITE_PATH` | `.data/loopa.db` | SQLite file; create the parent directory when using a custom path |
| `UPLOAD_DIR` | `.data/uploads` | Private image/video files and thumbnails; created during uploads |
| `TRUST_PROXY` | `false` | Set `true` only behind a trusted proxy that replaces forwarding headers and prevents direct app access |
| `SMTP_URL` | Unset | SMTP connection string; required for the mail worker and `npm start` |
| `MAIL_FROM` | Unset | Sender address; required for the mail worker and `npm start` |
| `REDIS_URL` | Unset | Optional shared rate-limit counters and messaging pub/sub |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Unset | Enable Google OAuth when both are set |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | Unset | Enable GitHub OAuth when both are set |

`DATABASE_URL` is not the runtime database setting. The retained Prisma scripts and PostgreSQL files are legacy references.

For OAuth, register the matching callback at the provider: `<APP_URL>/api/auth/oauth/google/callback` or `<APP_URL>/api/auth/oauth/github/callback`. Provider buttons appear only when configured. Test against the real provider before enabling it publicly.

## Email commands

After adding `SMTP_URL` and `MAIL_FROM` to `.env`, open a second terminal in the same application folder:

```sh
npm run mail:worker
```

For one batch, useful during controlled verification:

```sh
npm run mail:worker -- --once
```

The worker polls for pending mail every five seconds. The app queues mail; running the web server alone does not send it.

## Moving to another laptop

For a fresh start, clone and run the commands above. All application code comes from GitHub, but your previous accounts and content do not.

| Item | How it appears on the new laptop |
| --- | --- |
| Source, tests, scripts, schema, and docs | `git clone` |
| `node_modules/` | `npm ci` |
| `.env` | `npm run setup`, then re-enter private settings if needed |
| Development/production build output | `npm run dev` / `npm run build` |
| Previous accounts, posts, messages, and preferences | Restore your private SQLite backup |
| Previous uploaded photos/videos | Restore the matching media directory |

To retain existing content, stop the original web app and mail worker, privately back up the database **and** media, then restore them before starting the new copy. With default paths these live under `.data/`. If custom paths are configured, transfer those locations instead. See [backup and restore](DEPLOYMENT.md#backup-and-restore).

Install dependencies separately on Windows and WSL/Linux. Copying `node_modules` between operating systems can break native modules. A fresh clone is also a separate database unless you deliberately restore the existing one.

## Common problems

| Symptom | What to check |
| --- | --- |
| `npm` or `node` not found | Install Node 24 in the terminal environment you are using, then reopen that terminal |
| Missing `package.json` | Enter the actual application folder |
| Cannot load `node:sqlite` | Check `node --version`; use Node 24 |
| Missing/short JWT secret | Run setup if `.env` is absent; otherwise replace the placeholder privately |
| Port 3000 already in use | Stop the app that owns the port or use the alternate-port instructions below |
| Empty feed after cloning | Expected for a fresh database; create content or optionally seed an empty development database |
| Database cannot open | Check the parent directory exists and the process can write to it |
| `invalid_origin` response | Browser origin must match `APP_URL`, including scheme and port; avoid mixing `localhost` and `127.0.0.1` |
| No reset/verification email | Configure SMTP and sender, run the worker, and inspect failed queue counts |
| Video has no poster | Check `ffprobe -version` and `ffmpeg -version` in the app's environment |
| Old media is missing | Restore the upload directory matching the restored database |
| `npm start` rejects local settings | Use `npm run dev` for a local HTTP preview; production needs HTTPS and mail configuration |

For another development port, first change `APP_URL` in `.env` to `http://localhost:3001`, then run:

```sh
npm run dev -- --port 3001
```

Open http://localhost:3001. Update any OAuth callback configuration if you use it. Never remove `.data` as a way to resolve a build-cache issue.
